# Published TTS zero-interior WAV sparsification

The authorized cloud capacity action processed only a fixed inventory of already published `.cache/tts/<16hex>.wav` plus matching `.json` and existing `.json.lock` files. Both WAV and JSON mtimes had to be older than 600 seconds at the initial inventory. Of 1,291 initial pairs, 1,261 were eligible; 30 recent or otherwise ineligible pairs were excluded. Later creates and newly aged entries were not chased.

The existing cache protocol was read directly from `explainer/tts.py` and `explainer/cache_lock.py`: synthesis publishes the WAV and then JSON atomically while holding the metadata item's exclusive flock. The executor acquired that **same existing lock, nonblocking**, without creating a new lock or writing its contents. Under the lock it rechecked published identities, age, metadata completeness and full hashes, then proved the entire aligned interior zero before `fallocate --punch-hole --keep-size`. Recent, busy, missing, linked, nonregular, drifting or nonzero entries were not eligible for mutation. Metadata text, scripts, spoken strings and tokens were never recorded.

**1,253 WAVs were sparsified; eight nonzero interiors were skipped untouched.** There were no busy-lock, drift or physical-operation failures. Exact target allocation fell from 1,890,369,536 to 10,256,384 bytes, recovering **1,880,113,152 bytes (1.751 GiB)**. Filesystem free space rose from 812,007,424 to 2,688,512,000 bytes at 07:07:50 UTC while other Part 6 writes continued. The observed free-space delta is therefore separate from exact target allocation recovery. The 768 MiB render/extraction guard was unchanged.

Every processed WAV retains identical bytes, path, logical size, inode, device, mode, original mtime and atime. Header and unaligned tail bytes are unchanged. Original mtime/atime were explicitly restored; resulting ctime changes are recorded. Matching JSON and existing lock files retain their **full exact signatures**, including SHA256, size, timestamps, mode, inode and device. Reads used owner-authorized `O_NOATIME`; JSON contents were not copied into any receipt. There was no retagging, cache invalidation, deletion, reencoding, synthesis, provider/model call or network request.

All 306 protected numerical/model/corpus/current-Part-6 files retain exact signatures, and all 1,524 critical source/configuration files retain identical bytes. Full hash-only per-pair identities, zero-proof lengths, before/after metadata, protocol source hashes, execution code, fixed inventory and activity limits are bundled. Protected snapshots are included once because their decompressed before/after contents are identical; both original hashes are preserved in `summary.json`. Original forensics remain at hash-pinned private paths.

Host FD/maps visibility is partial, and no global absence of readers is claimed. Known visible consumers were skipped; the shared lock guarded writers. Existing readers would see identical bytes. This capacity receipt implies no speech synthesis, listening, pronunciation or synchronization approval.
